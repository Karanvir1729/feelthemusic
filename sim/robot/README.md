# Robot description (not in this repository)

The simulation work and `lamp/tests/test_spatial.py` both want the vendor robot description for
`lelamp_v1_pi5_feetech_r1`. It is **deliberately absent** from this repository.

It is generated by Human Computer Lab's `lelamp-external-runtime`, which its own README describes as
a private repository holding the restricted LeLamp V1 runtime, distributed for Stanford Robot Center
teaching, play and SDK testing. This repository is public, so the material does not belong here.

## This does not affect the build

`lamp/tests/test_spatial.py` guards its whole module:

```python
pytestmark = pytest.mark.skipif(not (ROBOT_DIR / "robot.urdf").exists(),
                                reason="vendor robot description not found")
```

A clean checkout therefore builds and tests green; those 9 tests report as skipped. `.gitignore`
blocks `*.stl`, `*.onnx` and `sim/robot/pi5_feetech_r1/` so the description cannot be committed here
by accident.

## Getting it

```sh
./sim/robot/fetch.sh                              # private mirror, for agents with access
./sim/robot/fetch.sh lelamp@lelamp-bfc5eta0.local # or straight off a lamp
FTM_ROBOT_DIR=sim/robot/pi5_feetech_r1 \
LELAMP_CALIBRATION_PATH=sim/robot/lelamp-calibration.json \
pytest lamp/tests
```

Both matter. With the description alone, 9 of the 11 spatial tests pass and two fail: `LampModel`
falls back to the vendor approximate joint map, which `spatial.py` itself notes overstates head tilt
by about 1.5x. `test_picture_motion_matches_what_was_measured_on_the_real_lamp` catches it as a 1.49x
error against a figure measured on the hardware. With the calibration too, all 11 pass.

The private mirror is `MeharPro/lelamp-robot-description`. Ask an operator for access; do not fork
it anywhere public.

## What it gives you

`robot.urdf` is 6 links and 5 revolute joints over 50 STL meshes, which Unity and MuJoCo both ingest
directly. `simulation.yaml` is a full hardware model — servo `update_hz 100`, command/read latency
4/6 ms, `max_velocity_per_s 140`, `max_acceleration_per_s2 420`, `backlash 1.0`, `deadband 0.2`,
`position_quantization 0.05`, plus the 93-pixel LED ring topology and diffuser geometry.

One number before you drive the panel: `channel_current_ma: 12.0` against `max_current_ma: 3000.0`
means 93 x 3 x 12 = 3348 mA at full white, above the panel's rating. The vendor default
`led_brightness: 0.3` keeps it near 1000 mA.
